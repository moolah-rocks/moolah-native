How CSV import works

Moolah recognises the shape of a CSV file by its structure, not by knowing your bank. This article explains what that means in practice.

What Moolah looks at

When you import a CSV, Moolah inspects the file itself — the header row, the column count, the delimiter, and the date format. Together these form a "file shape". Moolah doesn't read the file name or look up the bank that produced it. Two CSVs with the same column layout look identical to Moolah, even if they came from different banks.

What happens on a new shape

If the shape matches one Moolah has imported before, the file goes straight through. The rows turn into transactions and land in Recently Added.

If the shape is new, Moolah can't guess which column is the date, which is the amount, and so on. The file lands in Recently Added under Needs Setup. You map each column once — Date, Description, Amount, Payee — and pick which account the transactions belong to. Moolah saves the mapping as part of that file shape. The next file with the same columns imports without asking.

What this means for you

You set each new file shape up once. After that, the same export imports without further setup. This holds whether you download it monthly from your bank, drop it into a watched folder, or paste it in from a spreadsheet. If your bank changes its export format, that's a new shape, and Moolah will ask you to map it again.

To remove a learned file shape, go to Settings > Import, swipe the row, and select Delete. The next CSV with that shape will be treated as new and dropped into Needs Setup for fresh mapping.
