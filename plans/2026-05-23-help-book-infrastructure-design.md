# Help Book Infrastructure — Design

**Status:** Draft (2026-05-23)
**Author:** Adrian Sutton (with Claude)
**Worktree / branch:** `fix-duplicate-help-menu` / `worktree-fix-duplicate-help-menu`

## Summary

Moolah's Help menu currently shows two "Moolah Help" items: a system-default
entry generated by macOS (which routes to `NSHelpManager` but has nothing to
open) and a custom `CommandGroup` button pointing at `https://moolah.app/help`,
a URL that does not exist (the real domain is `moolah.rocks` and the path is
unpopulated). The custom group also contains Privacy Policy, Terms of Service,
and Release Notes buttons, all pointing at the wrong domain. `NSPrivacyPolicyURL`
in both `Info.plist` files has the same wrong domain.

This design replaces the broken help routing with a real Apple Help Book,
shared with a published web copy at `moolah.rocks/help`, and fixes the related
URL bugs. **This PR delivers the build pipeline, menu wiring, and a placeholder
"Welcome" page only**; the comprehensive table of contents and authored content
are explicitly deferred to follow-up PRs that touch only `Help/Topics/` and
`Help/TOC.json`.

## Goals

1. The macOS Help menu has exactly one "Moolah Help" entry, generated by the
   system, which opens HelpViewer.app at the bundled Help Book.
2. The bundled Help Book is content-shared with a web copy served from
   `moolah.rocks/help`; authoring is hand-written HTML body fragments wrapped
   per output target.
3. iOS gains a single Settings → Help row that opens
   `https://moolah.rocks/help` in Safari.
4. All `moolah.app` URL references in Swift and Info.plist files are corrected
   to `moolah.rocks`.
5. The help build pipeline is incremental — generation is a no-op when no input
   has changed.
6. Follow-up agents can author the comprehensive TOC and content without
   touching any infrastructure code.

## Non-goals

- Authoring the comprehensive Help Book content (a separate, multi-PR effort).
- Adding context-sensitive `NSHelpManager.openHelp(anchor:inBook:)` callsites
  in feature views — those land alongside the page they anchor at.
- Creating `moolah.rocks/release-notes`, `/privacy`, or `/terms` web pages;
  this PR only fixes the domain in existing references. Those pages remain
  404s until a separate content effort lands.
- iOS UI surfaces beyond the single Settings → Help row.
- Localisation — only `en.lproj` is generated. The pipeline does not preclude
  additional locales; nothing in the design hard-codes a single language.

## 1. Architecture

```
Help/
├── Topics/                                 # canonical HTML body fragments
│   └── welcome.html                        # <article>…</article> only
├── Shells/
│   ├── help-book.html.tmpl                 # Apple meta tags + minimal CSS + {{body}}
│   └── web.html.tmpl                       # site chrome + {{body}}
├── TOC.json                                # ordered topic list
├── Assets/
│   └── icon-32.png                         # Help Book icon
├── Styles/
│   ├── help-book.css                       # styles for HelpViewer.app
│   └── web.css                             # marketing-site styles
└── Metadata.plist                          # source for the bundle's Info.plist

tools/HelpGen/                              # Swift CLI, executableTarget
├── Package.swift
└── Sources/HelpGen/
    ├── main.swift                          # entry point + manifest fast-path
    ├── Inputs.swift                        # reads TOC, Topics, Shells, Assets, Styles, Metadata
    ├── Manifest.swift                      # SHA-256 hashing; .manifest.json read/write
    ├── TemplateRenderer.swift              # flat {{token}} substitution
    ├── HelpBookWriter.swift                # writes .help bundle, invokes hiutil
    └── WebWriter.swift                     # writes site/help/

# Generated outputs
Help/Build/Moolah.help/                     # gitignored, regenerated by HelpGen
site/help/                                  # checked in (served by GitHub Pages)
```

`just generate` invokes HelpGen (then xcodegen + CKDBSchemaGen). HelpGen
produces both output trees from the shared fragments and writes
`Help/Build/.manifest.json` for incremental rebuilds.

## 2. Incremental rebuild

Change detection lives in the `justfile`, matching the existing
`tools/CKDBSchemaGen` pattern. A stamp file at `.build/stamps/help-gen.stamp`
records the last successful generation. The `just build-help` recipe runs the
generator only when any of the following is true:

- the stamp is missing (fresh checkout, since `.build/` is gitignored);
- the output bundle directory `Help/Build/Moolah.help/` is missing or empty;
- the output site directory `site/help/` is missing;
- any file under `Help/` (Topics, Shells, Assets, Styles, `TOC.json`,
  `Metadata.plist`) is newer than the stamp;
- any Swift source under `tools/HelpGen/Sources/` is newer than the stamp.

On regen the recipe runs the Swift generator, then `/usr/bin/hiutil` for the
search index, then `touch`es the stamp. On a no-op the recipe exits silently
in under 50 ms.

HelpGen itself is **unconditional** — when invoked it always regenerates from
scratch. The single source of truth for "skip if unchanged" is the justfile
recipe, mirroring CKDBSchemaGen. This means no Xcode preBuildScript: developers
run `just generate` (or its alias `just build-help`) before `just build-mac`,
which is already the workflow for CKDB wire types.

## 4. Build wiring

### `Help/Metadata.plist`

```
CFBundleIdentifier         rocks.moolah.app.help
CFBundleName               Moolah Help
CFBundlePackageType        BNDL
CFBundleSignature          hbwr           # required by HelpViewer
CFBundleShortVersionString $(MARKETING_VERSION)
HPDBookTitle               Moolah Help
HPDBookAccessPath          welcome.html
HPDBookIconPath            shared/icon-32.png
HPDBookIndexPath           Moolah.helpindex
```

Token substitution for `$(MARKETING_VERSION)` happens at generate time using
the same value `project.yml` exposes.

### `App/Info-macOS.plist`

```xml
<key>CFBundleHelpBookFolder</key><string>Moolah.help</string>
<key>CFBundleHelpBookName</key><string>Moolah Help</string>
```

`CFBundleHelpBookName` must match `HPDBookTitle` exactly — the system looks up
the bundle by display title.

### `project.yml` (macOS target only)

```yaml
sources:
  # …existing entries…
  - path: Help/Build/Moolah.help
    buildPhase: resources
```

xcodegen tolerates missing source paths at generate time. Because `just
generate` runs `build-help` before `xcodegen generate`, the directory always
exists by the time xcodebuild scans it. No preBuildScript is added — staleness
is prevented by the `just generate` discipline already in place for CKDB.

### `justfile`

A new `build-help` recipe is added, modelled exactly on the existing
`generate` recipe's stamp-based block. `generate` invokes it before the
CKDB / xcodegen steps:

```bash
build-help:
    #!/usr/bin/env bash
    set -euo pipefail
    STAMP_DIR=".build/stamps"
    HELP_STAMP="$STAMP_DIR/help-gen.stamp"
    mkdir -p "$STAMP_DIR"

    needs=0
    if [ ! -f "$HELP_STAMP" ]; then
        needs=1
    elif [ ! -d "Help/Build/Moolah.help" ] || [ -z "$(ls -A Help/Build/Moolah.help 2>/dev/null)" ]; then
        needs=1
    elif [ ! -d "site/help" ]; then
        needs=1
    elif find Help -type f \( -name '*.html' -o -name '*.tmpl' -o -name '*.json' -o -name '*.plist' -o -name '*.css' -o -name '*.png' \) -newer "$HELP_STAMP" 2>/dev/null | grep -q .; then
        needs=1
    elif find tools/HelpGen/Sources -type f -name '*.swift' -newer "$HELP_STAMP" 2>/dev/null | grep -q .; then
        needs=1
    fi

    if [ "$needs" -eq 1 ]; then
        swift run --package-path tools/HelpGen help-gen
        /usr/bin/hiutil -Cf \
            "Help/Build/Moolah.help/Contents/Resources/en.lproj/Moolah.helpindex" \
            "Help/Build/Moolah.help/Contents/Resources/en.lproj"
        touch "$HELP_STAMP"
    fi
```

The existing `generate` recipe gains one line near the top of its bash body:

```bash
# ---- help-gen ----
just build-help
```
inserted before the `# ---- ckdb-schema-gen ----` block.

### `hiutil`

Invoked by the `just build-help` recipe immediately after the Swift generator
exits successfully (see the recipe snippet above). Lives in the justfile, not
inside HelpGen, so the bash recipe is the single source of truth for the
multi-step "generate → index → stamp" pipeline. Non-zero exit from `hiutil`
fails the recipe and skips the `touch`, so a stale stamp is not written.

### `.gitignore`

Add `Help/Build/`. `site/help/` is checked in — same precedent as the rest of
`site/`, which GitHub Pages serves directly.

### iOS target

No bundle wiring. iOS opens the published web copy at `moolah.rocks/help`
(§5).

## 6. HelpGen implementation

### Package layout

```
tools/HelpGen/
├── Package.swift                          # executableTarget, no third-party deps
└── Sources/HelpGen/
    ├── main.swift
    ├── Inputs.swift
    ├── TemplateRenderer.swift
    ├── HelpBookWriter.swift
    └── WebWriter.swift
```

### Dependencies

Foundation only. JSON decoding for `TOC.json` via `Codable`, `FileManager` for
I/O. No CryptoKit, no Process — the justfile invokes `hiutil` as a separate
step (see §4).

### TOC.json

```json
{
  "version": "1",
  "entries": [
    { "slug": "welcome", "title": "Welcome to Moolah", "parent": null }
  ]
}
```

JSON rather than YAML — Foundation parses it natively; Yams would add a
package dependency. Migration to YAML is a one-day change if ever needed.

### Template syntax

Flat `{{token}}` substitution only. No conditionals, no loops, no escape
rules. Supported tokens: `{{title}}`, `{{body}}`, `{{nav}}`, `{{slug}}`,
`{{version}}`. Body fragments are inserted verbatim; authors own the validity
of HTML inside fragments.

### Run flow

When invoked, HelpGen unconditionally regenerates (the `just build-help`
recipe owns skip-if-unchanged):

1. Load inputs: `Help/TOC.json`, `Help/Topics/*.html`, `Help/Shells/*.tmpl`,
   `Help/Assets/*`, `Help/Styles/*`, `Help/Metadata.plist`.
2. Delete `Help/Build/Moolah.help/` and `site/help/`.
3. For the Help Book: write `Contents/Info.plist` (from `Metadata.plist`),
   `en.lproj/*.html` (Topics + help-book shell), `en.lproj/styles.css`,
   `shared/icon-32.png`.
4. For the web copy: write `site/help/*.html` (Topics + web shell),
   `site/help/styles.css`.

(The `hiutil` index step is run by the justfile recipe after HelpGen exits.)

### Atomicity

Writes go through a sibling temp directory; success ends with
`FileManager.replaceItem(...)` swaps. No partial outputs left behind on
failure.

### Errors

All errors are fatal with a one-line message naming the offending file:
missing topic referenced by TOC, unknown token in a shell. No silent
fallbacks. `hiutil` failures are surfaced by the justfile recipe (which exits
non-zero without `touch`ing the stamp).

### Indexing host requirement

`hiutil` is macOS-only. Every CI lane is macOS today; if a Linux build ever
needs the help bundle, the justfile recipe is the place to add a host check.

## 7. Testing & verification

### HelpGen unit tests (`tools/HelpGen/Tests/HelpGenTests/`)

- TOC decoding: happy path + malformed JSON fails with a named error.
- Template rendering: every supported `{{token}}` substitutes correctly;
  unknown token raises.

### XCUITest regression for the reported bug (`MoolahUITests_macOS/`)

A new test opens the Help menu and asserts there is exactly one item titled
"Moolah Help". A `HelpMenuDriver` is added under
`MoolahUITests_macOS/Drivers/` per UI_TEST_GUIDE.md and reused by future tests.

### Build-pipeline assertion

New `just verify-help` recipe — runs `just build-help` twice and asserts the
second run does not invoke the Swift generator. Implemented by inspecting the
stamp mtime: first run advances it, second run leaves it unchanged. Added to
the macOS CI lane; skipped in iOS lanes (the bundle is macOS-only).

### Manual verification (PR checklist)

1. `just generate && just build-mac && just run-mac`. Help menu shows exactly
   one "Moolah Help" entry, opens HelpViewer at the welcome page.
2. HelpViewer's search field returns the welcome page when searched for
   "welcome".
3. Help → Privacy Policy / Release Notes / Terms — each opens the right
   `moolah.rocks/...` URL in Safari. (Pages will 404 until content lands;
   verify the URL is correct, not that the page renders.)
4. `just build-ios` + simulator. Settings → Help row → tap → Safari opens at
   `https://moolah.rocks/help`.
5. `just build-help` twice — second run is a silent no-op (stamp unchanged).

### Out of scope

- Content quality beyond `welcome.html`.
- That `moolah.rocks/help` is live (GitHub Pages picks up `site/help/` on its
  own cadence).
- That `moolah.rocks/release-notes`, `/privacy`, `/terms` exist.

## 9. Risks

- **xcodegen + missing-source ordering.** If `Help/Build/Moolah.help` is
  absent at xcodegen time, the project still generates, but the resource
  reference is brittle. Mitigation: `just build-help` runs before `xcodegen
  generate` inside the `just generate` recipe, so the directory always exists
  by the time xcodegen scans it.
- **hiutil availability.** Tool ships with macOS, but a future macOS release
  could deprecate it. Mitigation: the generator names the absolute path; a
  later switch to a replacement indexer is a one-file change in
  `HelpBookWriter.swift`.
- **`CFBundleHelpBookName` exact-match requirement.** Quietly fails (no Help
  Book opens) if it diverges from `HPDBookTitle`. Mitigation: both values are
  derived from the same constant in HelpGen; a unit test asserts they match.
- **Site path conventions.** `site/help/` is generated by HelpGen and checked
  in. If a future site refactor moves the marketing pages, both the wrapping
  shell and the path constant in `WebWriter.swift` must move together.
